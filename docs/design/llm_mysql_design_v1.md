# 大模型驱动的数据分析中台设计（v1）

随着大模型能力的爆发，智能中台系统完全可以支持从主动写SQL/拉报表”转向“被动语义驱动”。本项目旨在通过 **LLM (豆包-1-8)** 与 **MySQL (数据层)** 的深联动，构建一套具备元数据感知、多步多维归因分析、以及自动化运维能力的智能中台。解决了数据分析门槛高、报表需求繁琐、运维复杂的三大核心痛点。

---

## 1. 业务背景与痛点分析

### 1.1 趋势：BI&AI
传统的 BI 系统本质上是“预设路径的可视化”，无法应对业务人员“临时起意”的复杂归因需求。

### 1.2 核心痛点
在传统数据分析与智能化融合的过程中，往往面临多方面挑战。首先是**语义问题**：业务层的指标表达（例如“毛利率下降”）与底层数据库的物理实现（如 `SUM(price - cost) / SUM(price)`）之间存在理解成本，这种从业务语义到数据计算逻辑的映射依赖人工经验，理解成本高且容易出错。

其次是**计算复杂性问题**，尤其在归因分析等场景中，往往需要进行多表关联、跨维度聚合以及多级下钻操作，SQL 编写过程复杂繁琐，不仅效率低下，还极易引入逻辑错误。

最后是**运维黑盒问题**，对于大多数开发者而言，查询性能瓶颈难以定位，导致数据库长期运行在非最优状态，缺乏有效的调优手段与可解释性。



## 2. 总体架构设计 (System Architecture)

### 2.1 架构设计原则
*   **分层设计**：遵循 DDD 原则，将 AI 推理与底层存储彻底解耦。
*   **插件化思维链**：支持针对不同业务域（分析、报表、运维）挂载不同的 Prompt 模板。
*   **数据隔离与脱敏**：在 DDL 注入层实现严格的物理视图隔离。

### 2.2 逻辑架构
系统分为四层：
1.  **Interfaces**：基于 Vue 3 + Element Plus，利用 SSE (Server-Sent Events) 实现异步进度推送。
2.  **Application**：负责分析任务的状态管理和 CoT 执行计划的调度。
3.  **Domain**：核心业务逻辑。包含 Analysis（归因拆解）、Reporting（图表协议）、Ops（SQL诊断）三个子域。
4.  **Infrastructure**：包含 Ark SDK 适配器、MySQL 执行器、元数据实时扫描引擎。



## 3. 核心技术模块攻坚

### 3.1 动态元数据引擎
*   **llm自我感知**：通过查询 `information_schema` 动态获取表结构、字段注释。
*   **上下文注入**：在请求 LLM 时实时注入 DDL，确保 AI 永远基于最新的库表结构进行 SQL 生成。

### 3.2 深度归因分析：CoT 拆解协议
*   **Level 1: 计划**：将抽象问题（如“GMV为什么下降”）拆解为 JSON 执行计划。
*   **Level 2: 执行**：并行调度 SQL 生成与执行，涵盖时间、区域、品类等多个维度。
*   **Level 3: 汇聚**：将真实执行数据喂回 AI，生成具备商业逻辑的最终洞察报告。

### 3.3 智能报表：图表自动选型
*   **语义映射**：AI 自动根据查询结果特征（离散/连续/占比）决策 ECharts 图表类型（Pie/Bar/Line）。
*   **配置桥接**：将 AI 意图转换为标准 ECharts 配置协议，实现“一句话生成看板”。



## 4. 运维诊断与安全保障 (Ops & Security)

### 4.1 AI-运维链路
*   **慢SQL诊断**：动态抓取活跃会话，利用 AI 对 `EXPLAIN` 执行计划进行语义化解读。
*   **生成建议**：AI 直接吐出 `CREATE INDEX` 等优化语句，降低对高级 DBA 的依赖。

### 4.2 安全防御体系
*   **高危审计**：基于正则与词法的双向黑名单过滤，严禁 `DROP`, `DELETE` 等破坏性指令。
*   **权限收敛**：数据库连接层仅开启 `SELECT` 权限，实现物理隔离。

## 6. 改进方向

在之后的发展方向中，该系统将重点围绕智能化增强、协同机制优化以及多数据源扩展三个层面持续演进。首先，在 **RAG 增强方面**，计划引入指标字典与业务语义的向量化能力，通过构建统一的语义索引体系，将业务指标、维度定义与历史查询经验进行向量存储与检索，从而进一步降低自然语言到 SQL 转换过程中的语义偏差，提升查询生成的准确性与业务一致性；在 **多 Agent 协作机制** 上，将引入专门的质检 Agent，对生成的 SQL 进行自动化校验与优化，包括语法正确性检查、性能风险评估以及业务逻辑合理性验证，从而形成“生成—审核—优化”的闭环链路，提升系统整体可靠性与可控性；在 **多源数据接入能力** 上，系统将逐步支持包括 ClickHouse等多种分析型数据库引擎，实现多数据源统一查询与调度能力，从而增强系统在复杂异构数据环境下的适应性与扩展性。
